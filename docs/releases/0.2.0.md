# Player Lab 0.2.0

This release adds a Web startup comparison, reusable configuration profiles and
independent Android reference applications. The main Web lab continues to use
Player v8 for configuration, UI customization and API inspection.

## Player Web X and startup comparison

The separate [startup comparison](https://kazuhide.github.io/player-lab/web/comparison.html)
uses Player Web X 10.3.1, hls.js 1.7.4 and Shaka Player 5.3.3 with matched
fixed-quality HLS media. Choose SDK import mode, settings and repeat count;
inspect individual outcomes before comparing summaries. Candidate evaluation
and subsequent confirmation remain separate.

Read the [Player Web X introduction](https://kazuhide.github.io/player-lab/guide/web-startup-comparison/#player-web-x)
and [implementation guide](https://kazuhide.github.io/player-lab/guide/web-startup-integration/).
The [2026-11-01 tables](https://kazuhide.github.io/player-lab/guide/test-results/#web-startup-2026-11-01)
and [recorded report data](https://raw.githubusercontent.com/kazuhide/player-lab/b02b242232c661360c5304ba3493b511e8e028bd/docs/web-startup-results-2026-11-01.json)
retain their original SDK versions, content, environment and conditions. The
lowest startup time depends on those conditions; the results do not establish
a universally fastest player or optimal values for every setting. App
Play→Playing is distinct from Bitmovin Analytics VST. Browser-managed caching
does not establish a warm cache, and the comparison does not measure total CPU
utilization or process memory.

Save JSON uses export schema 2, retaining SDK versions, settings, outcomes,
intervals and safe observations. It adds a separate save UTC timestamp and each
trial's start UTC and coarse environment. Unknown observations retain null and
a reason. Environment values are browser-reported classifications or estimates,
not verified hardware measurements. Credentials, source URLs and raw SDK
metadata are excluded.

## Configuration profiles and playback controls

The Web and native labs can save named configuration profiles and check the SDK
version before applying them. Profiles retain local drafts; confirm the source
and settings before applying one to another playback session.

Live-rewind preferences now update supported embedded controls. API actions
check the current source and playback state, disabling operations whose
prerequisites are absent. The tvOS System UI limitation remains documented.

## Independent Android references

The [learning reference](https://github.com/kazuhide/player-lab/tree/v0.2.0/references/elearning)
provides course and lesson selection, transcript search and per-demo-learner
resume positions. The
[sports streaming reference](https://github.com/kazuhide/player-lab/tree/v0.2.0/references/sports-streaming)
provides live events, clips and prepared archive handoff. Each application has
its own Android project, configuration and English and Japanese documentation.

Their optional playback-quality dashboards offer a key-free demo view and a
separate measured view with an explicit fetch action. They explain the
Analytics metrics and connect report rows to Bitmovin Dashboard. Fetching
measured data requires account API access in the local server; it is not a
credential-free Pages feature.

## Updating a source checkout

Refresh workspace dependencies with `pnpm install --frozen-lockfile`, then
follow the tagged platform README to regenerate and rebuild native hosts.
Existing main Web and native launch commands remain available. The independent
references use their own configuration files and build commands; a main-app
`.env` is not automatically loaded by either reference.
