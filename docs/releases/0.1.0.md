# Player Lab 0.1.0

This is the first versioned release of Player Lab, a collection of Bitmovin
Player configuration and UI samples for Web, iOS/tvOS, Android/Fire TV,
React Native and Vega OS.

## Try the app

- Open the [Web app](https://kazuhide.github.io/player-lab/web/) to change player
  and source settings, try playback APIs, switch UI examples and read applied code.
- Use the [English guide](https://kazuhide.github.io/player-lab/guide/) or
  [Japanese guide](https://kazuhide.github.io/player-lab/ja/guide/) for controls,
  native setup, API availability and Analytics.
- Build native apps from the tagged source using [Setup](https://github.com/kazuhide/player-lab/blob/v0.1.0/docs/SETUP.md). The release
  does not distribute signed mobile or TV apps.

## Scope

The public Web app runs on GitHub Pages. It can send playback data through the
configured Analytics collector. Account-level Analytics queries require the
local server and are hidden on Pages. API availability and device requirements
are listed in the guide; an exposed SDK entry does not establish that every
hardware-dependent feature has been exercised on a physical device.

Public test streams can change or become unavailable. Your own sources, DRM,
casting and native apps may need credentials, supported hardware or license
allow-list entries. Account API secrets must remain on the server.

## Build identification

The Web app and guide show their product version and source commit. SDK versions
have their own release cycle and are listed separately in the guide.

The GitHub release retains the validated Pages archive, file checksums,
provenance and a CI attestation bundle. A CI attestation is a signed statement
that binds the archive to the repository workflow and source commit that
produced it. Pages uses these retained bytes, including when restoring a
previous release; it does not rebuild that source during publication.
