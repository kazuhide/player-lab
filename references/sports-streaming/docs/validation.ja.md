# 検証記録

[English](validation.md) · [日本語](validation.ja.md)

Player Android 3.172.0と統合Analytics collector 3.35.2を使って2026年10月28日に実行した検証の記録です。端末での実行にはローカルに設定したデモ用ライセンスとこのリファレンスの自作素材を使いました。認証情報、端末のシリアル番号、非公開の配信元、生の端末ログは含めていません。

ガイドの画面キャプチャは2026年10月29日に、野球の素材を再生した日英の実アプリ画面で更新しました。更新したのは画面キャプチャであり、以下の再生・Castの検証結果は当初の日付と範囲のままです。

字幕は別途、自然な描画、実際の映像終了時の消去、再再生、致命的なSourceエラーからの復帰を確認しました。実機でのイベント確認では編集アーカイブへの引き継ぎ中に、Sourceに対応するUTC変換と一時停止の意図が維持されることを確認しました。

新しくロードしたVODのSourceは、再生を開始していなくてもReadyになる場合があります。このときSDKの`isPlaying`と`isPaused`は両方ともfalseになり得ます。アプリはSourceの準備完了と、実際の位置が変わらないことから、再生しない意図が保たれているかを確認し、SDKが返した生のフラグは別に残します。その後にPlayを明示的に実行したら、そのSourceの時計が進む必要があります。

端末・受信機とイベント全体の継続時間を確認する場合は、後述のコマンドを使います。確認記録にはアプリ・テストAPKの識別情報と、実際の実行件数、結果、素材の条件を残します。ソースの読取りやコンパイルだけでは受信機での再生や受信機側のAnalytics収集を確認したことにはなりません。

<a id="playback-clocks-at-event-finalization"></a>
## イベント終了時の再生時刻

条件を制御した別のWeb検証では、Player 8.281.0とChrome 156.0.8078.73を使いました。同じ180秒のコンテンツを、新しいSourceをロードせずにライブから有限長へ変更しました。HLSはプログラム日時タグを含むMPEG-TS、DASHは配信開始時刻を基準にする分割MP4を使いました。マニフェストを変更する前に一時停止し、変更後も一時停止を維持しました。

| Webの配信形式 | 終了処理の前後の既定・絶対時刻（秒） | 終了処理の前後の相対時刻（秒） | 再生時間 |
| --- | --- | --- | --- |
| HLS | 1793181047.315292、変化なし | 120.219292、変化なし | `Infinity` → 180 |
| DASH | 1793181052.031333、変化なし | 120.025000、変化なし | `Infinity` → 180 |

両方ともPlayerとSourceを維持し、`SourceLoaded`イベントは1回だけでした。終了処理後は`isLive() == false`になり、シーク可能範囲もUnix時刻の基準を保ちました。これらはWebのAPIについての観測であり、Android、Cast、ほかのHLS構成での動作を確認したものではありません。[APIの比較と引き継ぎ規則](implementation.ja.md#playback-position-and-unix-time)を参照してください。

追加のWeb DASH検証では後述のAndroid確認と同じ素材を使い、配信サーバーも同じ保持区間の規則で動作させました。最後の静的マニフェストは180秒のコンテンツを宣言しつつ、セグメントの時系列情報は約60秒分だけを保持します。この素材に対して、Web 8.281.0は再生時間180秒とUnix時刻基準のシーク可能範囲を返し、Android 3.172.0は再生時間59.999秒と0–59.999の範囲を返しました。このマニフェスト構成で計測したSDKの値の違いであり、すべてのVODに当てはまる規則ではありません。このWeb検証でも、一時停止中の既定・絶対時刻1793186922.750と相対時刻149.926は変わらず、Sourceのロードは1回でした。

Android 3.172.0の実機DASH確認では、短いイベントの終了前後で、同じSource、impression、要求、一時停止したフレームを維持しました。SDKの相対座標は連続していましたが、生の返り値の表し方が変わりました。

| Android DASHの項目 | 終了処理前 | 終了処理後 |
| --- | --- | --- |
| `currentTime`（秒） | 1793163695.741 | 107.742 |
| `playbackTimeOffsetToAbsoluteTime`（秒） | 0 | 0 |
| `playbackTimeOffsetToRelativeTime`（秒） | −1793163588 | 0 |
| SDKの相対座標（秒） | 107.741 | 107.742 |
| 再生時間（秒） | `Infinity` | 59.999 |
| シーク可能範囲（秒） | ライブ中は0–0 | 0–59.999 |

維持された一時停止位置は、新たに示されたシーク可能範囲では有効なシーク先ではありません。このコンテンツには移動する保持区間がありました。有限の再生時間になったことは、以前のバッファー内のフレームがその区間の0秒を基準に再計算されたことを意味しません。シークの前にはその時点の範囲を取得してください。明示的にシークすると、SDKから新たに有効な絶対時刻の対応情報が得られない限り、それまで保持していたUTC変換は無効になります。この観測はAPIの値の変化を確認したもので、アーカイブへの引き継ぎの成功や、イベント全体の継続時間を確認したものではありません。

<a id="event-duration-and-source-preparation"></a>
## イベントの継続時間と素材の準備

短時間の操作確認と、イベント全体の継続時間の確認は別です。[連続再生の手順](../android/README.ja.md#normal-event-endurance-check)では実際の経過時間、映像フレームの変化、ライブ時計の進行、保持期間を過ぎた位置からの復帰、明示的なアーカイブへの引き継ぎを確認する必要があります。抽出したプロセスメモリと取得可能な温度状態は、その端末・実行での観測値であり、メモリリークがないことや温度特性を保証するものではありません。

今回の確認では、30分の連続再生は対象外としました。任意で実行するためのコマンドはローカルでの確認用に残しています。

保存したスポーツ映像の原本、クリップ、編集アーカイブについては、クラウドVODの準備が完了しました。HLS/DASH両方のマニフェストと参照先フラグメントを取得し、ハッシュと媒体情報を確認し、切り出し・編集の境界で抽出したフレームを比較しました。ローカルのライブ配信サーバーはこれらの素材を実時間で順次配信します。この配信サーバーや完了したVODジョブだけでは、停止したクラウドLiveの録画からアーカイブを作成したことの確認にはなりません。

<a id="repeat-the-checks"></a>
## 検証を再実行する

[設定手順](../README.ja.md#requirements-and-configuration)に従い、[端末実行ドライバーと任意のCastコマンド](../android/README.ja.md#reproducible-device-checks)を使ってください。全テストの実行にはPlayerライセンス、実際のimpressionの連続性を確認するためのAnalyticsライセンス、端末から到達できる映像配信元が必要です。実行件数、ランナーの終了状態、APKのハッシュは、Git管理対象外の`android/build/device-tests/`に記録します。

ドライバーはインストール済みアプリのダイジェストが選択したローカルAPKと完全に一致する場合だけ、そのAPKを再利用します。一致しない場合は、新しいAPKをインストールして内容を照合します。受信機の自動選択やADBサーバーの再起動は行いません。端末・受信機の結果はビルド、HTTP配信、クラウドでの素材準備の結果とは分けて扱います。
