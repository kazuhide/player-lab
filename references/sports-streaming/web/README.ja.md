# Web で試合を再生する

[English](README.md) · [日本語](README.ja.md) · [素材の準備](../README.ja.md)

Bitmovin Player Web 8.284.0 と UI 4.23.1 を使います。カタログ、映像 ID、再生素材はネイティブアプリと共通です。ブラウザーの言語設定に合わせて英語または日本語で表示します。

## ローカルで起動する

[素材の準備](../README.ja.md)に従って、このアプリの素材を生成し、配信サーバーを起動してください。カタログの既定の URL は `http://127.0.0.1:8622/catalog.json` です。Node.js 24.19 以降を使い、このディレクトリで次のコマンドを実行します。

```sh
npm ci
cp .env.example .env.local
```

`VITE_PUBLIC_PLAYER_LICENSE_KEY` に、`localhost` での再生を許可した Player ライセンスを設定してください。素材の配信元を変更した場合は、`VITE_MEDIA_BASE_URL` に配信元ディレクトリの URL を設定します。再生品質を計測する場合は、`VITE_PUBLIC_ANALYTICS_LICENSE_KEY` にデモ用の Analytics ライセンスを設定してください。これらの設定値はブラウザーから読み取れます。アカウントの API キーは分析画面のサーバーだけに設定します。

```sh
npm run dev
```

`http://localhost:5182` を開いてください。環境設定を変更した場合は開発サーバーを再起動します。静的に配信する場合は、視聴端末から到達できる素材の URL を指定して `npm run build` を実行し、ライセンスで許可したホストから `dist/` を配信してください。HTTPS のページから再生する場合は、素材の配信元も HTTPS にして CORS を有効にします。

## 再生する

イベントを選び、ライブ、クリップ、準備済みの録画を開きます。スポーツ用UIでは15秒ずつ戻したり進めたり、DVRのスライダーで視聴位置を選んだりできます。クリップから戻るときはライブの最新位置を選べます。元のライブの視聴位置を取得できていれば、DVRの範囲内にあることを確かめてから、その位置へ移動します。ライブ配信中にクリップを最後まで再生すると、ライブの最新位置に戻ります。

ライブの配信終了と録画の準備状態は別々に表示します。配信が終了しても視聴中のDVRは維持されます。録画の準備ができたら、ライブの視聴時刻に対応する録画内の位置から再生できます。編集済みの録画では残した区間だけが対応します。時刻が不明な場合、カットした区間にいた場合、録画の終端に達する場合は、別の再生方法を選んでください。自動継続をオンにすると、位置の対応を確認できた場合に限り、配信終了後に選択した録画へ移ります。初期状態では、そのイベントの全編録画が選ばれています。移動先の再生可能範囲を確認し、再生または一時停止の状態を引き継ぎます。自動での状態取得が止まった場合は、状態の更新ボタンで再度取得できます。

HLS と DASH を切り替えても、選んだ映像と再生・一時停止の状態を引き継ぎます。クリップや録画では再生位置を、ライブでは確認できた視聴時刻を使います。その映像で選んだ形式を利用できない場合は、元の形式での視聴が続きます。クリップから元の DVR 位置に戻る操作は、視聴位置が配信中の範囲にある間だけ表示されます。クリップを閉じる前に素材サーバーの範囲を再確認し、ライブを開いた後に SDK の再生可能範囲も確認します。通信の順序にかかわらず、素材サーバーで新しく観測した時刻と範囲を優先します。ブラウザー標準の HLS 再生では、再生中の動画から取得した配信時刻と再生可能範囲で視聴位置を確認します。配信が終了した DVR では残っているセグメントの範囲を確認します。最後まで見た録画で形式を切り替えた場合は、再生ボタンで先頭から見直せます。DASH の場合は、この素材の MPD に記された配信開始時刻と、実際にデコードしたセグメントの時刻から視聴位置の UTC を求めます。時刻の対応が確認できない映像では、次の再生位置を選んでください。

UI を切り替えても同じ Player、Source、字幕レンダラー、Analytics セッションを使います。アプリの操作画面では、ブラウザーが対応していれば全画面表示に切り替えられます。SDK が対応する環境では、ピクチャ・イン・ピクチャへの切り替えや AirPlay の出力先の選択もできます。診断画面には映像 ID と数値のエラーコードを含む直近30件までの SDK イベントを表示します。

診断画面の「引き継ぎ記録をダウンロード」で、ライブから録画に移るリクエストを直近200件まで JSON に保存できます。一時停止中は移動先の映像を読み取れたとき、再生中はさらに再生時刻が進んだときに引き継ぎが確定します。確認中に手動で位置を変えたり出力先を切り替えたりすると、そのリクエストの確認は打ち切ります。録画内の位置へ移動できた時点から、再生位置と再生・一時停止の状態を再試行に使えます。その後の再生エラーでは、元の記録を維持し、直近で確認した録画内の位置から再試行します。結果を確認できなかったリクエストも記録に残ります。記録はページを閉じると消去されます。再生 URL、受信機の品質指標、Analytics のカスタムデータは含まれません。

## 確認する

```sh
npm test
npm run build
```

Google Chrome を用意し、生成済みの素材を配信して、ライセンスを設定したアプリを起動します。その状態でブラウザーテストを実行してください。

```sh
FORMAT=hls npm run test:browser
FORMAT=dash npm run test:browser
```

macOS の WebKit で HLS 再生を確認する場合は、`npx playwright install webkit` で Playwright の WebKit をインストールし、`BROWSER=webkit FORMAT=hls npm run test:browser` を実行してください。別のポートで起動したアプリを確認するには `APP_URL` を設定します。

一時停止した DVR の位置への復帰と録画への自動継続を試す場合は、短縮版の試合を新しく開始してください。開始から10秒以上たったら `RUN_LIVE=1 FORMAT=hls npm run test:browser` を実行します。テストは配信終了と録画の準備完了まで待ちます。保存位置に戻るとき、アプリは読み込み画面の裏で一時的に音を消して再生し、新しく開いたライブ映像の時刻を読み取ります。そこで一時停止して目的の位置に移り、移動後の時刻を確認してから、元の再生または一時停止の状態に戻します。

短縮版の試合が終了したら、既定の60秒の DVR ウィンドウを使い、`RUN_FINALIZED=1 npm run test:browser` で配信形式の切り替え、引き継ぎ記録、デコードエラー後の再開を確認できます。WebKit の標準 HLS 再生では `BROWSER=webkit RUN_FINALIZED=1 npm run test:browser` を実行します。
