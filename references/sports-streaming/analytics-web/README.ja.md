# スポーツ配信の再生品質ダッシュボード

[English](README.md) · [日本語](README.ja.md)

スポーツ配信リファレンスの再生品質を照会し、端末に保存した引き継ぎ記録を確認するWebアプリです。画面は日本語と英語に対応しています。サーバーと静的なWeb画面は、Androidのビルドとは独立して実行できます。

<a id="setup"></a>
## セットアップ

Node.js 24系の24.13以降を使用します。

```sh
cd analytics-web
cp .env.example .env
npm ci
```

`BITMOVIN_API_KEY`にはAnalyticsの読取り照会権限を持つBitmovinアカウントのAPIキーを、`BITMOVIN_ANALYTICS_LICENSE_KEY`にはこのアプリ用のAnalyticsライセンスキーを設定してください。どちらもサーバー側の設定です。PlayerライセンスキーはアカウントのAPIキーとは異なります。任意設定の`PORT`の初期値は`9052`です。

読み込むのは、このディレクトリの`.env`だけです。親ディレクトリやAndroid側の設定は使用しません。`.env`は公開しないでください。キーをブラウザーへ返すことはありません。

```sh
npm start
```

`http://127.0.0.1:9052`を開き、期間、映像、映像の種類を選んで「更新する」を押します。自動更新は初期状態では無効です。有効にすると、再生品質のページが表示されている間は60秒ごとに更新します。未設定、データなし、値が0、照会失敗は別の状態として表示します。このダッシュボードは収集済みのデータを照会するもので、データ収集や再生セッションの作成は開始しません。

<a id="playback-quality"></a>
## 再生品質

サーバーは対象プラットフォームをAndroidに固定し、`config.mjs`で宣言した7つの`sports:SP-*`映像IDに照会を限定しています。映像の種類を選ぶフィルターも、このIDの集合を使います。custom dataの項目は使用しません。送信側の計測値だけでは受信機の品質を確認できないため、受信機との比較は無効です。

| 指標 | 照会 | 表示 |
| --- | --- | --- |
| 再生開始数 | `VIDEO_STARTUPTIME > 0`の`IMPRESSION_ID`をカウント | 回数 |
| 視聴時間 | `PLAYED > 0`の`PLAYED`を合計 | ミリ秒を3,600,000で割って時間に換算 |
| 再生開始待ち時間の中央値 | 正の`VIDEO_STARTUPTIME`の中央値 | ミリ秒を1,000で割って秒に換算 |
| 再生開始待ち時間の95%点 | 正の`VIDEO_STARTUPTIME`の95パーセンタイル | ミリ秒を1,000で割って秒に換算 |
| 再バッファ割合 | `REBUFFER_PERCENTAGE`の平均 | API標準のパーセント値 |
| エラー率 | `ERROR_PERCENTAGE`の平均 | API標準のパーセント値 |

照会では任意のコンテキスト列を明示的に無効にし、ダッシュボードは指標の結果形式だけを読み取ります。カードは期間全体の照会結果を表示し、時間別のグラフと映像ごとの比較にはそれぞれ別の照会を使います。時間別のパーセンタイルを平均して期間全体の値にしたり、欠けている時間帯を0で補ったり、欠損区間を線でつないだりはしません。グラフにはデータの表も付けています。取得時刻は、サーバーがAPIの応答を受け取った時刻です。最新の元サンプルが記録された時刻ではありません。

Bitmovin Dashboardと比較するときは、期間と映像IDを揃えてください。指標の照会は[公式の照会例](https://developer.bitmovin.com/playback/docs/how-to-recreate-dashboard-queries-via-the-api-1)と[Percentile APIリファレンス](https://developer.bitmovin.com/playback/reference/postanalyticsqueriespercentile)に従っています。

<a id="handoff-records"></a>
## 引き継ぎ記録

「引継ぎの確認」はローカルのJSONファイルをブラウザー内で読み込みます。ファイルを照会サーバーやBitmovinへアップロードすることはありません。読み込むたびに、それまでの記録を置き換えます。Androidアプリから書き出した記録を使うか、「架空の表示例を開く」を選んでください。表示例は実測ではなく、8件の要求に成功6件、失敗1件、確認待ち1件を含む架空データです。結果が確定した要求の成功率は`6 / 7 = 85.7%`、全要求に対する確認済み成功の割合は`6 / 8 = 75%`です。

入力形式は次のとおりです。

```json
{
  "schemaVersion": 1,
  "source": "local-device-records",
  "period": { "start": "2026-10-28T00:00:00.000Z", "end": "2026-10-28T01:00:00.000Z" },
  "records": [{
    "requestId": "handoff-1",
    "requestedAt": "2026-10-28T00:30:00.000Z",
    "eventId": "SP-EVENT-A",
    "transition": "live-to-archive",
    "requested": { "videoId": "sports:SP-ARCH-EVENT", "positionMs": 90000, "playWhenReady": false },
    "confirmed": { "videoId": "sports:SP-ARCH-EVENT", "positionMs": 90000, "playWhenReady": false, "positionAdvanced": false },
    "failure": null,
    "receiverQoe": null
  }]
}
```

上の例は形式の説明用であり、実測結果を書き出したものではありません。`transition`は`live-to-archive`または`cast`です。`failure`は`null`、`load-failed`、`position-mismatch`、`disconnected`のいずれかです。成功とするには、映像が一致し、位置の差が1,000ミリ秒以内で、再生・一時停止の意図も一致する必要があります。要求したライブ端の位置が不明な場合は`null`のまま確認待ちとし、0へ置き換えません。確認結果の位置には実際に取得した0以上の整数を使います。再生中は位置の進行を、一時停止中は一時停止状態の一致を確認します。この証拠がない要求は、明示的な失敗がない限り確認待ちのままです。受信機の再生品質は`null`のままにします。

ファイルの上限は1 MiB、重複しない要求は200件です。未知のフィールド、対象外の映像ID、不正な時刻、推定した受信機の指標は拒否します。名前、URL、キー、自由記述の診断メッセージを記録に含めないでください。引き継ぎの結果は標準のQuery API指標とは分けて扱います。

<a id="server-limits-and-checks"></a>
## サーバーの制限と確認方法

サーバーは`127.0.0.1`だけで待ち受け、HostとOriginを検証します。配信するのは、固定した静的ファイル、`GET /api/config`、`GET /api/qoe`だけです。クライアントから上流URL、ライセンス、アカウントキー、集計軸、プラットフォームを指定することはできません。認証のないローカル開発用サーバーのため、外部へ公開しないでください。

照会期間は最大7日間で、時間別グラフは1時間単位です。上流への同時リクエストは最大3件、照会バッチ全体の制限時間は10秒です。完全に取得できた結果は15秒間キャッシュしますが、取得時刻は変更しません。同じ要求の処理は共有し、保持するバッチは最大2つ、キャッシュする選択条件は最大16件です。ページごとに200行と`offset`を使い、ページ取得回数と応答サイズにも上限を設けています。レート制限時は`Retry-After`に従い、制限時間内で短い再試行を最大1回行います。取得に失敗した値や欠けている値は未取得のままにし、照会失敗をデモ値で補うことはありません。更新失敗後に以前の成功結果を残す場合は、そのことを画面に表示します。

```sh
npm test
npm run build
```

テスト対象は、照会形式、プラットフォーム・映像のフィルター、ページ分割、並列処理、キャッシュ、レート制限、制限時間、応答サイズ、Origin検証、秘密情報を含まないエラー、古い応答の破棄、グラフの欠損区間、引き継ぎ記録の証拠と読込み規則です。`build`はモジュールと静的ファイルを確認します。生成済みのバンドルや実行時依存パッケージは不要です。
