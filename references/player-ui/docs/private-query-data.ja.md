# 非公開のQuery集計結果を表示する

[English](private-query-data.md) · [日本語](private-query-data.ja.md) · [計算方法](analytics-data.ja.md)

ローカルの開発サーバーではQueryで事前に集計した結果を、対応するHLS動画と一緒に表示できます。
読み込むのはリポジトリ外で明示的に指定したファイルだけです。
ブラウザーも開発サーバーもAnalytics APIへの問い合わせは行いません。
通常のデモは引き続き同梱の合成データを使います。

## 件数を準備する

[全体と区間の件数を求めるQuery](analytics-data.ja.md#集約queryだけを使う)で、
動画のバージョン、ライセンス、集計期間、対象条件を揃えます。
画質別に分けず、各impressionを1件として数えてください。
各区間は`VIDEOTIME_START < endMs`かつ`VIDEOTIME_END > startMs`で重なる記録を数えます。
アカウントAPIキーはバッチの実行環境に保持します。

グラフは区間ごとの件数を`sessionCount`で割って表示します。
値はその区間を少しでも見た再生記録の割合です。区間内で見た長さの割合とは異なります。
繰り返したパスを件数から判別することはできないため、再視聴の値は取得なしとして扱います。
この指標には`watched-impression-incidence-v1`という別のバージョンを使います。

すべての区間を取得してから`complete: true`にしてください。
リクエストの失敗を件数ゼロへ置き換えてはいけません。
集計期間を固定し、同時リクエスト数に上限を設け、全体の検証後にファイルを置き換えます。

次の例は4秒の動画を表します。URLと件数は仮の値です。
ソース、動画の識別子、長さ、期間、すべての件数を、同じ動画の集計結果へ置き換えてください。

```json
{
  "schemaVersion": 1,
  "metricVersion": "watched-impression-incidence-v1",
  "complete": true,
  "content": { "id": "example-video", "revision": "v1", "durationMs": 4000 },
  "source": { "hls": "https://example.com/video/master.m3u8" },
  "period": {
    "start": "2026-01-01T00:00:00.000Z",
    "end": "2026-01-02T00:00:00.000Z"
  },
  "generatedAt": "2026-01-02T00:00:00.000Z",
  "sessionCount": 10,
  "bucketWidthMs": 2000,
  "buckets": [
    { "startMs": 0, "endMs": 2000, "impressions": 10 },
    { "startMs": 2000, "endMs": 4000, "impressions": 4 }
  ]
}
```

位置と長さはミリ秒、日時はUTCで指定します。区間は先頭から末尾まで順に揃え、
必要なら最後の区間だけ短くします。件数は0から10億までの整数です。
区間の件数は全体の件数を超えられません。
対象記録がある場合、取得が完了した区間の件数ゼロは`0%`です。
対象記録がない場合は割合を算出しません。

[検証処理](../src/query-incidence.ts)は項目の欠落や余分な項目、URLのユーザー情報に含まれる認証情報、
未完了の集計、矛盾する件数を拒否します。上限は512 KiB、2,000区間です。
ソースにはブラウザーで再生できるHTTPSのHLS URLを指定してください。
署名付きURLには有効期限があります。過去のAnalytics記録から取得しても期限は延びません。

## 非公開データで開く

完成したファイルを公開用のチェックアウトの外へ保存し、所有者だけが読める権限にします。
リファレンスのディレクトリで、ローカル接続だけを受け付ける開発サーバーを起動してください。

```sh
chmod 600 /absolute/private/path/query-data.json
PLAYER_UI_PRIVATE_QUERY_FILE=/absolute/private/path/query-data.json npm run dev
```

`http://localhost:5199/?data=private&lang=ja`を開きます。
画面はデータを「Query API」と表示し、見られた区間を選択した状態になります。再視聴は選択できません。
JSONリンクから取得するのはローカルの集計結果であり、個別の再生履歴ではありません。
組み込みコードの例には共通のエンドポイントを使い、非公開のソースURLは表示しません。
集計ファイルを置き換えた後はページを再読み込みしてください。

Playerが取得した動画の長さと、指定した長さが一致しない場合はグラフを隠します。
長さが同じでも編集内容が同じとは限らないため、集計側でも動画のバージョンとソースを一致させてください。

固定の`/__private/query-data`で`GET`と`HEAD`だけを受け付けます。
外部サイトからのアクセス、プロキシ経由のリクエスト、このチェックアウト内のファイル、
所有者以外に権限があるファイルは拒否します。応答はキャッシュしません。
この経路で外部URL、ファイルパス、API認証情報を指定することはできません。

ローカル開発用の画面です。トンネルやプロキシでポートを外部へ公開しないでください。
データ、ダウンロードしたJSON、画面キャプチャも公開対象に含めないでください。
動画の再生とグラフの表示には、ソースURLと集計値をローカルのブラウザーへ渡します。

## 公開デモをビルドする

非公開データ用のサーバーを止め、ビルド環境から`PLAYER_UI_PRIVATE_QUERY_FILE`を外します。
この変数が設定されていると`npm run build`は停止します。
ファイルは`dist/`へコピーされず、ビルドしたサイトには非公開データ用のエンドポイントもありません。
本番のCMSへ組み込む場合は、利用者の権限に応じて集計結果を配信する仕組みを別途用意してください。
